# 018 — Header and footer titled-rule support across formatters

## MOST Goal

Generalize the existing `Heading` titled-rule pattern (`─── Title · field ─────...`) along two independent axes it was previously restricted on: **position** (header-only → header + footer) and **formatter coverage** (Table-only → Table/Tree/Expanded/Text/Yaml/Toml/Sql), so any comment-capable or plain-text formatter can bracket its output with a consistent opening and/or closing titled rule.

- **Motivated:** `Heading` (`src/config/table_heading.rs`, formerly `TableCaption`, renamed under task 009) already renders a titled divider rule, but only ever *above* a table (`TableConfig::with_heading()`) and only for `TableFormatter`. Both restrictions are historical accidents of where the feature was first built, not deliberate design boundaries — the rendering logic (`content_str()`, lead/trail width arithmetic, CJK-safe `unicode_visual_len` measurement) has no inherent dependency on "above" placement or on the Table formatter specifically. A footer position (closing rule below the output) and coverage across every other formatter that already emits fixed-width or comment-syntax text closes an obvious, low-risk gap using code that already exists and is already battle-tested (BUG-015/016/017 fixes apply automatically to every new call site because they all route through one shared function).
- **Observable:** `TableConfig::with_footer(Heading)` renders a titled rule after the bottom border, symmetric to `with_heading()` before the top border; both may be set independently or together with no interference. The same header/footer pair becomes available on `TreeFormatter`, `ExpandedFormatter`, and `TextFormatter` configs, and on `Yaml`/`Toml`/`Sql` formatters wrapped in each format's native comment syntax (`#` / `--`). `Json`, `Logfmt`, and `Html` are explicitly excluded (no comment syntax for the first two; `Html` deferred pending its own design). Every change is additive — `Option<Heading>` fields defaulting to `None` — so no existing caller's output changes unless it opts in.
- **Scoped:** one shared rendering primitive (`render_rule_if_present`, refactored from the Table-only `render_heading_if_present`) parameterized by the `Heading` value and target width rather than reading a fixed config field, reused verbatim at every new call site; per-formatter config additions (`footer`/`with_footer()`/`footer_ref()` on `TableConfig`, mirrored on Tree/Expanded/Text configs); comment-wrapped variants for Yaml/Toml/Sql; matching test coverage per formatter mirroring the existing `table_heading_test.rs` pattern; `docs/feature/007_table_heading.md`, `docs/algorithm/007_heading_rendering.md`, `docs/invariant/005_heading.md`, `docs/api/003_config_types.md` and their `tests/docs/` counterparts extended (not replaced) to describe both positions and all covered formatters. No change to `Heading`'s own data shape, to any existing formatter's default (no-heading/no-footer) output, or to Json/Logfmt/Html.
- **Testable:** `cargo nextest run -p data_fmt --all-features --test table_heading_test --test table_footer_test` (Phase 1, done) plus one mirrored test file per subsequent phase; `cargo clippy -p data_fmt --all-targets --all-features -- -D warnings` clean after every phase; full-suite regression (`cargo nextest run -p data_fmt --all-features`) shows zero change to any pre-existing test.

- **Phase 4 (pending):** `TextFormatter` heading + footer — no separate `TextConfig` type exists today; fields are added directly to `TextFormatter` rather than inventing a config type that nothing else needs (YAGNI).
- **Phase 5 (pending):** `Yaml`/`Toml`/`Sql` formatters — heading/footer wrapped in each format's native comment prefix (`#` for Yaml/Toml, `--` for Sql), reusing the same width algorithm.

## Out of Scope

- `Json` (no comment syntax to host a non-data line), `Logfmt` (no comment convention), `Html` (deferred — needs its own header/footer design, e.g. `<!-- -->` vs. a visible banner element; not a mechanical port of the text-rule pattern).
- Any change to `Heading`'s own fields, `content_str()` format, or the `·`/`─` constants.
- Any change to existing no-heading/no-footer output on any formatter (Invariant 1 — passthrough — holds throughout).
- A crate version bump: consistent with task 009 (39 new `with_` builders, no bump) rather than 016/017 (bumped because a specific external consumer needed a pinned version) — no external consumer has requested a pinned version for this feature; deferred unless one materializes.
